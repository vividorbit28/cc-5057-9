# 飞行探索关卡航道生成器（受约束空间曲线工程）

这不是跑酷关卡模板，而是一套**以飞行器运动包络为硬约束的三维空间曲线工程工具**：输入必须穿越的门、禁止体积和飞行器转弯/爬升能力，由内核生成连续可飞的三维航线、可视引导结构，并用一个受支持运动模型的飞行器真实跟随、核对跟随误差。任何无法满足的约束都会作为违规区段如实标出，**不会通过无限转向速度或缩小碰撞体让路线“看起来可飞”**。

---

## 1. 怎样启动界面

界面是一个纯静态 ES 模块 + Three.js 应用，所有依赖（`three.module.js`、`OrbitControls.js`）已复制到 `vendor/`，**无需联网、无需打包**。

```bash
cd flight-course-editor

# 方式一：Python 自带静态服务器
python3 -m http.server 8080
# 然后浏览器打开 http://localhost:8080/

# 方式二：Node（如已安装 npx）
npx serve . -l 8080
# 浏览器打开 http://localhost:8080/
```

> 不能直接双击 `index.html` 用 `file://` 打开——ES 模块的 import map 与本地模块需要 http(s) 源。

打开后即进入**关卡编辑视窗**：左侧是规划/包络/回放/图层面板，中间是可拖动的三维视窗，右侧是结果区（航道运动与障碍间距）和违反条件区段列表。

## 2. 架构：内核驱动控件，失败反馈回内核

```
src/
  kernel/            与 DOM/Three 完全解耦的纯计算内核（可在 Node 直接跑）
    math.js          向量、包围体（盒/球/柱）、净空距离、线段间距
    spline.js        向心 Catmull-Rom + 每点切线控制柄 + 弧长重采样
    frame.js         双反射旋转最小化框架（RMF）+ 协调转弯倾斜 + 翻滚稳定性
    speed.js         模式 A：曲率/爬升/门速窗反解航速，加减速双向传播
    reshape.js       模式 B：锁速下切线松弛 + 插入引导点的局部曲线重塑
    constraints.js   门穿越/净空/自近接/转弯半径/爬升/倾斜全包络校核
    simulation.js    受支持运动模型飞行器 + PD 路径跟随 + 跟随误差
    gate-windows.js  门可达时间区间（快/慢航速剖面）+ 开门通行调度
    construction.js  控制点优化 / 分段候选搜索 + 门反向约束 + 修整策略
    experiments.js   急弯与狭窄禁区的曲率上限 / 碰撞距离复算实验
    course.js        编排：样条→采样→框架→航速→校核→仿真→调度
    scenarios.js     高低穿越 / 急转限制 / 相邻航道 / 不可飞演示
  editor/
    scene.js         Three.js 场景图（管带、违规红段、门、障碍、引导、姿态、飞机、候选叠加）
    interaction.js   轨道相机 + 射线拾取 + 控制点/门拖拽
    main.js          控制器：所有控件事件都调用内核，再用内核结果重绘
index.html / styles/editor.css
tests/               76 项无头测试（内核 13 + 曲线求解/调度/实验 17 + 场景图 13 + DOM 接线 33）
```

数据流是单向闭环：**控件操作 → 内核重建/重算 → 内核返回可行性与违规 → 界面渲染**。界面本身不判定可飞性，只翻译内核结果；失败（违规、不可达速度窗、仿真丢失航迹）会回到右侧违规列表并在三维视窗标红。

## 3. 两种航速/曲线处理办法

### 模式 A：固定门位，重定航速
几何与门位锁定。内核对每个弧长站求最大可行速度（转弯 `v²/(g·tan φmax)`、爬升率 `vzMax/|sin γ|`、门 `vMin/vMax` 窗），再以前向加速、后向减速两次传播保证整条速度表物理可达。在检查器里拖动某站速度手柄后，**前向与后向引导点按时间头距（guidance headway）整体回算**，不是只改一个数字。门速下限若在加减速能力内不可达，报 `speed-window-conflict` 错误。

### 模式 B：锁定航速，局部重塑曲线
速度表锁定为硬需求，门位固定。自由变量是各控制点的**切线方向覆盖**以及在门之间**插入的额外引导点**。迭代时在稠密弧长采样上测量曲率/爬升/净空违规，把最近控制点的切线向缓解方向松弛（投影松弛），收敛停滞则在最长段插入中点继续。收敛判据与约束校核用的是同一个包络；迭代到上限仍无法消除的违规会作为 `residualViolations` 硬返回，绝不隐藏。

## 4. 为什么“把控制点用光滑曲线连起来”不算可飞

内核在稠密弧长采样上同时强制以下条件，任一不满足即生成定位到弧长区间的违规：

- **转弯半径**：`R = 1/κ ≥ v²/(g·tan φmax)`，与当前速度直接挂钩；
- **爬升角 / 垂直速率**：`|γ| ≤ γmax`、`|v·sin γ| ≤ vzMax`，并限制爬升角变化率；
- **门穿越**：在样条参数空间稠密扫描门平面（折返航线会多次穿同一平面，按航线顺序取下一个正向穿越），校验门内横/竖向净空与航向对齐；
- **禁止体积净空**：分段自适应求到盒/球/柱表面的距离，小于碰撞半径即违规；
- **通道宽度与自近接**：非相邻航段（按弧长忽略同一局部带）间距必须大于通道直径加可见分离裕度，防止管道自重叠；
- **姿态框架稳定**：RMF 保证近直线段不翻滚，倾斜由曲率/速度计算并受滚转速率限制，检测直线段姿态突变；
- **速度配置与弯道负担的关系**：弯越急、允许速度越低，速度规划与曲率包络耦合，而非各自独立。

仿真器是带有限极限的点质量/运动学模型（速度区间、加减速、`φmax`、滚转速率、`γmax`、`vzMax`），PD 跟随带横向纠偏与偏航阻尼。横向 RMS/峰值偏差、是否跑完全程、是否冲出可恢复通道都会量化输出。

## 5. 内置样例

| 样例 | 压测的约束 |
|---|---|
| 高低穿越 | 下潜穿架空障碍→爬升高位门→俯冲入低位门；爬升角、垂直速率、竖向门净空 |
| 急转限制 | 窄门间 90° 急弯 + 内侧建筑；模式 A 门前减速 vs 模式 B 锁速重塑大半径弧 |
| 相邻航道 | 机库走廊内折返平行贴近；自近接、通道直径、可见引导分离 |
| 不可飞演示 | 门被障碍吞没、弯道超最小半径、门速窗不可达；验证违规标红与失败反馈 |

## 6. 视窗操作

- 鼠标左键拖动 **青色控制点**改曲线；拖动 **橙色门框**移动门（关联控制点同步）。
- 点击控制点/门在右下检查器编辑：控制点可调该站指令航速（触发模式 A 回算）；门可调半宽/半高与 `vMin/vMax` 速度窗。
- 右侧违规列表点击任意区段，相机飞到对应弧长位置；红色=错误，琥珀色=警告。
- 左下回放：播放/暂停/复位、进度条、0.25–3× 倍速；黄色飞行器沿仿真轨迹运动并显示姿态。
- 图层开关：通道包络带、引导环、姿态三轴、禁止体积、障碍间距标注。
- HUD 与结果区实时显示可飞性、错误/警告数、航道长度、最小转弯半径、最大爬升角、最小障碍间距、碰撞半径、横向 RMS/峰值偏差与跟随容差。

## 7. 飞行航道生产的图形入口

飞行航道原型**不是只存在于实验文本**，以下功能全部在关卡编辑视窗（第 1 节启动后的页面）内可操作，命令行仅作辅助：

| 图形入口（左侧面板） | 操作 | 内核输出到哪里 |
|---|---|---|
| **门可达时间窗与开放调度** | 表格列出每个门的可达区间 `[tMin, tMax]` 与分配通行窗；点“缩短中门开放窗”触发调度拒绝，点“重拟合被拒航段”尝试重拟合 | 拒绝航段在表中标红，异常提示区显示原因；无法兼顾曲率与时窗时保留旧航道并明示 |
| **航道构造策略（曲线求解比较）** | 勾选“叠加分段候选搜索的航迹”在视窗叠加虚线候选；勾选“以飞行门反向约束曲率”；点“比较四种策略”列出曲率上限/碰撞距离/门序 | 比较表与控制点优化/分段搜索共享同一组门、障碍与转弯能力输入 |
| **实验：曲率上限与碰撞距离** | 点“复算急弯 / 狭窄禁区实验” | 表格由 `runCurveExperiments()` 实时计算，测试逐行复检 |
| 视窗拖拽 + 回放 | 拖动青色控制点改曲线、橙色门移位，然后“播放”让飞行器沿仿真轨迹运动 | 拖动即触发内核重建；结果区的净空/转弯半径与候选叠加层随之更新 |

所有面板数据来自内核实际运算：净空由 `segmentClearance` 分段求距，曲率来自样条解析导数，时间窗由快/慢航速剖面梯形积分得到；界面只翻译这些结果，不自行判定可飞性。

## 8. 实验：曲率上限与碰撞距离（代码复算）

这两张表由 `src/kernel/experiments.js` 的 `runCurveExperiments()` 生成，`tests/experiments-test.js` 用 `verifyExperimentRow()` 逐行复检，**表中没有手填数字**。几何以等弧长步长布置，使 Catmull-Rom 在弯道上与直道采样密度一致；否则弯道结点处的 C1 曲率突变会让“最小半径”失去意义。

急弯：90° 弯道半径 → 实测最小半径 / 最小碰撞间距（碰撞半径 2.2 m）：

| 弯道半径 m | 实测最小半径 m | 最小间距 m | 几何可行 |
|---|---|---|---|
| 14 | 9 | 2.00 | 否（净空 < 碰撞半径） |
| 20 | 15 | 2.00 | 否 |
| 26 | 19 | 4.40 | 是 |
| 34 | 30 | 7.60 | 是 |
| 44 | 44 | 11.53 | 是 |
| 56 | 51 | 16.34 | 是 |
| 70 | 62 | 21.95 | 是 |

狭窄禁区：缝隙半宽 → 最小碰撞间距 / 可达性（直道，实测曲率≈0，半径记为“直”）：

| 缝隙半宽 m | 实测最小半径 | 最小间距 m | 几何可行 |
|---|---|---|---|
| 1 | 直 | 1.00 | 否（< 碰撞半径） |
| 2 | 直 | 2.00 | 否 |
| 3 | 直 | 3.00 | 是 |
| 4 | 直 | 4.00 | 是 |
| 6 | 直 | 6.00 | 是 |
| 9 | 直 | 9.00 | 是 |
| 14 | 直 | 14.00 | 是 |

读法：急弯表里“实测最小半径”随弯道半径单调上升，但恒小于名义半径——Catmull-Rom 在直道—弯道结点处有可测的曲率过冲，这正是“看起来平滑”与“曲率包络”之间的差距。狭窄禁区表里最小间距恒等于缝隙半宽（减去碰撞半径前的表面距离），半宽 < 2.2 m 时直接判为不可行。

### 曲率度量修正记录

原 `Spline._derivs` 用 5 点二阶差分 `p₊₂ − 2p₊₁ + 2p₋₁ − p₋₂`，该式不含 `p(u)`，对任何二次曲线恒为零，导致实测曲率是数值噪声：一条精确 14 m 圆弧被读成约 57 m。现已改为对所在 Hermite 段解析求一阶/二阶导数，精确圆在内部采样上读到 14.0 m，方可作为实验数据。

## 9. 无头测试

无浏览器环境下用 Node 验证全部计算与场景图/DOM 接线（共 76 项）：

```bash
npm test
# 或分项：
npm run test:kernel       # 几何包络、两种模式、仿真跟随（13 项）
npm run test:experiments  # 门可达窗口/调度、曲线求解比较、复算实验（17 项）
npm run test:scene        # Three.js 场景图构建（桩渲染器，13 项）
npm run test:dom          # happy-dom 下真实控件事件链路（33 项）
```

说明：当前容器无 root 权限安装 Chromium 系统库，因此 WebGL 像素级渲染通过“桩渲染器 + 真实 Three 场景图构建”覆盖；在有显示器/浏览器的机器上按第 1 节启动即可看到实际 WebGL 画面与拖拽回放。
